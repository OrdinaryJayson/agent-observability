## 已提供的共同基底

公共模型已经包含可选 agent_ids 的 UUID/长度/去重检查，保持旧配置兼容。B 将来检查数据库身份，C 将来实现绑定继承；当前基底 HTTP 对显式绑定请求返回 409 FEATURE_NOT_AVAILABLE，避免身份验证尚未实现时假装支持。不绑定的原型流程不变。公共模型并不表示 v1 的绑定功能已经完成。

HTTP JSON 是独立合成的形状样例，不是真实性能结果或完整 OpenAPI，也不是可运行的后端 mock。A 在自己的测试中依据样例提供拦截，B 实现时同时遵循 05/08 的完整参数语义。样例之间不保证跨接口统计对账，实际业务验收应以数据库真实数据核对。成员不得修改样例以迁就自己实现。

## 验收分两层

模块交付：A 用冻结样例和 mock 证明页面与边界；B 用真实 PostgreSQL 与固定结果证明业务/SQL；C 用纯模型和原型证明模拟/采集/生成。所有人都能独立完成模块 PR，不等待其他人的新代码。

负责人整体验收：合并三个分支后，以真实服务替换 A 的测试 mock、真实 C 结果替换 B 测试替身，检查 Agent 绑定、日志/统计对账、实验/历史/超时及全部页面。独立模块通过不自动等于 v1 发布通过。仍有接口运行时关系，统一由负责人在最终集成阶段验证，不能省略。

本轮仅抽出公共契约和调整任务，不减少 V01–V09，不提前实现三人的正式业务功能。新增依赖和公共协议问题由负责人集中处理。
